PayPal AI Hackathon 2026

ShopCrew

AI agents run a small online shop. PayPal moves the money. The owner supervises — and asks why — in one live control room.

The idea in one minute

Imagine Maya. She sells candles alone. Mornings disappear into refund emails, "are we out of stock?", and checking competitor prices.

Without ShopCrew

She does every refund, every restock order, and every price tweak by hand — and still worries she moved money too fast.

With ShopCrew

Agents propose the work. A policy gate decides what is safe. PayPal executes. Maya approves, edits, stops — or just asks why.

Who does what

Customer service

Refunds & replies

Reads complaints, drafts reply emails, and proposes PayPal refunds. Every message lands in the Inbox tab with the agent's reasoning visible.

Inventory

Restocks & negotiates

Forecasts demand, negotiates unit cost with the supplier over up to three rounds, then pays via PayPal Payouts. The full negotiation transcript is shown in the control room.

Pricing

Price changes

Watches demand and competitor prices with a log-log elasticity model, then proposes careful moves. An orchestrator blocks discounts when stock is thin.

A fourth piece — the orchestrator — runs after each agent and blocks unsafe combinations before they reach the policy gate.

How money stays safe

Agents never "just send money." Every idea becomes a proposal. A policy engine checks limits, budgets, and a kill switch before PayPal is called.

Agent proposes → Policy gate checks → Owner approves / edits → PayPal executes → Webhook confirms → Grid updates live

Rollback is built in. Price changes restore the previous price; unclaimed payouts can be cancelled. Refunds cannot be reversed (PayPal does not allow it), so they sit in human review above the auto-approve limit.

Policy at a glance

Agent Can auto-approve Daily budget Hard blocks
Customer service Refund ≤ $15 and ≤ 50% of the order $150 Repeat refunders always wait; reply proposals always wait
Inventory Preferred supplier, spend ≤ $200 $1,000 Discount blocked when days of cover < lead time + 2
Pricing Absolute change ≤ 5%, never over 20%, margin ≥ 25% — Orchestrator veto on margin and cover

One switch — Pause all agents — stops everything immediately.

The control room

An AG Grid Enterprise control room with live SSE updates. Type plain English ("show refunds over $20") and the grid filters itself via the AG Grid AI Toolkit + natural-language route.

What's new

📬

Customer Inbox tab

Every complaint message is shown with its day, category, sentiment, and the agent's draft reply. Expand any row to read the full message, see the agent's reasoning, approve or reject the reply — all without leaving the grid.

🤝

Supplier negotiation timeline

The inventory agent negotiates unit cost with the supplier across up to three rounds. Each offer, counter-offer, and acceptance is shown as a colour-coded timeline with the saving vs. list price in dollars and percent.

💬

Ask the agent why

Every proposal has an "Ask" panel at the bottom. Three quick chips cover the most common questions; there's also a free-text box. The agent answers in plain English from stored facts, with no API key needed in replay mode.

💸

Live PayPal money loop

After two real sandbox checkouts, "Link capture pool" in the Orders grid maps those captures to the seeded orders. Advance one day and the scripted refunds hit PayPal for real — no DRY- labels. Webhooks confirm each move.

What is real vs. simulated

Simulated

  • ~180 days of sales history (Holt-Winters seeded)
  • Competitor prices
  • Customer complaint inbox (fixture text)
  • Supplier negotiation responses

Sandbox-real (with PayPal keys)

  • Checkout capture (PayPal JS SDK v6)
  • Refunds (Agent Toolkit + REST fallback)
  • Supplier payouts (Payouts API)
  • Webhooks updating the grid live

Tech, briefly

PayPal Agent Toolkit Orders v2 + JS SDK v6 Payouts API Webhooks + signature verify AG Grid Enterprise AG Charts AG Studio Fastify + Drizzle + PGlite React + Vite Vercel AI SDK Gemini / Groq / replay Render

One app process: storefront + API + agents + SSE live updates. Money credentials stay on the server. Idempotency keys stop double-charges. Holt-Winters and OLS elasticity are implemented in TypeScript, not an LLM.

Why this is different

Not a "chatbot that talks about payments." ShopCrew is agents propose → policy gate → PayPal executes → owner supervises and asks why. That loop — closed, auditable, rollback-able — is the product.

Built for solo sellers who need real automation without losing control of their money.
